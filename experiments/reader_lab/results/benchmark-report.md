Status of this commit: research, implementation, widget tests, and two debug APK compiles. Not a completed device benchmark. No weighted score is assigned.

## Environment

See `environment.json`.

- Host: Ubuntu cloud VM. Not an Android device.
- Flutter 3.47.9 stable, Dart 3.13.7, framework `c197ca5199`.
- Reader Lab debug APK compiled with Android compileSdk 36. It was not installed.
- Readium lab debug APK compiled with compileSdk 37. It was not installed.
- No emulator image was installed. No `adb devices` row existed.
- Rendering backend, refresh rate, and panel type on a device: not measured.

## Functional results

Status words: `widget_pass` is a Flutter widget test. `source` is a reading of the engine, not a run. `not_tested` means no device or emulator observation. `compile` means the debug APK linked. Compilation is not behavior.

### epub_rtl

Source, read in this workspace from tag 0.1.0: scroll mode is one `CustomScrollView` with two lazy sliver lists centered on an anchor spine index. Parsed chapters are cached up to 8. A 1 px rule is drawn between chapters. Locations are spine index plus block index plus a within-block fraction. The fraction is not the bookmark identity. There is no EPUB CFI. The package says saved epub_view CFIs cannot be converted.

### flutter_epub_viewer

The lab sets `EpubFlow.scrolled`, `EpubManager.continuous`, `snap: false`, and `useSnapAnimationAndroid: false`. The package default manager is already `continuous`. epub.js uses that manager for its continuous scrolled example. The package's own known-issues list says scrolled chapter navigation can land past the requested position (their issue 27). That is an upstream warning, not a measurement we took.

`onRelocated` provides `startCfi` and `endCfi`. Those are stored as the exact locator when non-empty. `progress` is stored and labeled approximate. Spine index is not on that callback, so the lab does not invent one.

| Check | Status |
| --- | --- |
| F-001 through F-010 | not_tested |
| Debug APK contains the plugin | compile |

WebView behavior, CFI restoration, and memory were not observed.

### foliate-js

The host is original. It loads `foliate-view`, calls `open` on a loopback URL, sets `flow` to `scrolled`, removes `animated` and `no-continuous-scroll` if present, then calls `init` with a CFI when one was saved. `relocate` events supply the CFI used as the identity. The section fraction is stored as approximate progress.

The paginator at the pinned commit preloads the next and previous section into the same scroll container while scrolled, unless `no-continuous-scroll` or `no-preload` is set. That is the mechanism described in Readest's scrolled-mode fixes. The README at that commit still says the paginator has no continuous scrolling. The code and the README disagree. The code is what the host enables. Runtime behavior was not observed, so this is not a pass.

`fetch` of the EPUB in foliate-js reads the whole file into a blob. That is a memory limit of this integration. Fixed-layout rendering is not vendored, because `fixed-layout.js` imports an npm polyfill that is not bundled. The corpus is reflowable.

| F-001 through F-010 | not_tested |
| Host configuration | the host source asks for scrolled flow and does not set `no-continuous-scroll` |
| Debug APK contains the assets | compile |

### flutter_readium

`EPUBPreferences.scroll` is documented in 0.9.1 as vertical scroll instead of horizontal pagination. The platform interface's presentation enum says a scrolled spine item is rendered as a separate scrollable document. The widget exposes `disablePageTurnsWhileScrolling`, which exists because a gesture can still change resource while scrolling. The lab sets `scroll: true` and leaves page turns enabled, and it shows that instruction on screen.

The Readium locator JSON is kept whole. `totalProgression` is labeled approximate. A CSS selector or highlighted quote, when the locator has one, is the anchor id. There is no EPUB CFI in this plugin's locator.

| Check | Status |
| --- | --- |
| F-001 and F-002 | source: the model is per resource. Device confirmation not_tested. Not counted as a measured fail, and not counted as a pass |
| F-003 through F-010 | not_tested |
| Debug APK | compile, compileSdk 37, `FlutterFragmentActivity`, desugaring enabled |

An engine whose documented model does not cross spine items inside one scroll is not a primary candidate. A device run is still required before writing "failed on device".

## Known limitations of the lab

- epub_rtl draws a 1 px chapter rule and does not expose CFI.
- epub_rtl center and end alignment are marked unsupported. The settings sheet does not fake them.
- flutter_epub_viewer typography is CSS pushed through its theme API. Whether the book honors it is not tested.
- Foliate typography is a lab stylesheet injected on the public `load` event, with `!important`. foliate-js has no typography method. Publisher CSS can still win where `!important` does not apply.
- Foliate loads the whole EPUB into the WebView via `fetch`.
- Readium font size is sent as `preferences.fontSize / 18` because the plugin's field is a ratio (`1.0` = 100%), not a pixel size. Page margins are sent as `marginPx / 20`. Both mappings are lab conventions, not values confirmed on a device. `publisherStyles: false` is set so those fields can apply; that drops publisher CSS.
- Bookmark files are JSON in the app documents directory. The widget test observes the in-memory list. The store unit test observes the file when the future is awaited.
- Diagnostics frame time is shown only while the overlay is open and is not written to the CSV.
